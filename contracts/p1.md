# P1 接口契约：语料与检索

对应 [重构设计](../doc/platform-redesign.md) 第四、五、十节。本文件是 api、engine、web 三方并行开发的共同依据；修改须同步三方并记录 change-log。

## 一 工程结构

```text
apps/web/          React + TS + Vite + Ant Design
services/api/      FastAPI（包 services.api）
services/worker/   Python 任务执行器（包 services.worker），PostgreSQL 队列
engine/            Python 包：parsers、nlp、cwb、query；不依赖数据库和 HTTP
deploy/            compose.yaml、Dockerfile.api、Dockerfile.worker、Dockerfile.web
tests/             pytest；engine 与 api 分目录
```

根 `pyproject.toml` 管理全部 Python 依赖（uv）。CWB 与 Stanza 只在容器内可用；本机 Windows 开发通过 `docker compose run --rm test` 跑需要它们的测试。

## 二 HTTP 接口

前缀 `/api`。JSON 请求与响应。认证用 HttpOnly Cookie 会话，非 GET 请求校验 `Origin`。错误统一为 `{"error": {"code": "...", "message": "..."}}`，状态码 400 / 401 / 403 / 404 / 409 / 422。列表接口接受 `page`（从 1 起）、`page_size`（默认 50，最大 200），返回 `{"items": [...], "total": n}`。

### 认证与项目

| 方法 路径 | 请求 | 响应 |
| --- | --- | --- |
| POST /auth/login | `{email, password}` | `User` |
| POST /auth/logout | — | 204 |
| GET /auth/me | — | `User` |
| GET /projects | — | 列表 `Project` |
| POST /projects | `{name}` | `Project` |
| GET /projects/{id} | — | `Project` |
| GET /projects/{id}/members | — | 列表 `Member` |
| GET /users?email= | 精确邮箱 | `User`；用于按邮箱添加成员，404 表示不存在 |

`User = {id, email, display_name, is_admin}`；`Project = {id, name, role, created_at}`；`Member = {user_id, email, role}`；`role ∈ owner | editor | annotator | viewer`。

### 检索

| 方法 路径 | 请求 | 响应 |
| --- | --- | --- |
| POST /search/parse | `{query}` | `ParseResult` |
| POST /search | `SearchRequest` | `SearchResult` |
| GET /search/context | `document_id`、`sentence_index`、`before=1`、`after=1` | `{document: Document, sentences: [{index, text, highlight: [start, end]|null}]}` |
| POST /search/export | `SearchRequest + {format: csv|xlsx}` | `Job`（kind = export） |
| GET /projects/{id}/queries | — | 列表 `SavedQuery` |
| POST /projects/{id}/queries | `{name, query, scope}` | `SavedQuery` |
| DELETE /queries/{id} | — | 204 |

```text
SearchRequest = {scope: {corpus_id} | {subcorpus_id}, query: string,
                 context: {unit: char|sentence|paragraph, size: 40},
                 sort: position|left|right|random, seed?: int,
                 page: 1, page_size: 50, search_id?: string}
  search_id 可选：翻页或重取计数时带上首次返回的 search_id，服务端复用同一结果而不重新检索
ParseResult = {ok: bool, anchor: string, conditions: [{op: "+"|"-", text}],
               tokens: [{kind, text}], error: {position, message}|null}
SearchResult = {search_id, parse: ParseResult,
                counts: {hits, sentences, documents, complete: bool},
                items: [Hit], page, page_size}
Hit = {hit_id, document_id, document_title, sentence_index, left, match, right,
       start_cp, end_cp, metadata: {}, aligned: [{language, text}]}
  start_cp / end_cp 为文档全文码点；hit_id = "<document_id>:<start_cp>-<end_cp>"
```

GET /search/context 另接受可选 `start_cp`、`end_cp`（文档码点），用于计算 `highlight`。POST /search/export 另接受可选 `project_id`，使内置语料的导出出现在该项目任务列表。管理员可 `POST /corpora` 创建内置语料。

`counts.complete=false` 表示计数在 20 秒内未完成，前端显示"计算中"并带 `search_id` 重新 POST /search。`highlight` 的码点相对该句 `text`。所有"列表"响应统一为 `{items, total}` 信封，`metadata-fields` 除外（裸数组）。`hit_id` 稳定，供导出和后续保存证据使用。

## 三 engine 包接口

engine 由 worker 和 api 调用，不访问数据库。

```python
# engine/model.py
@dataclass
class Token:    start: int; end: int; form: str; pos: str | None = None; lemma: str | None = None
                head: int | None = None; deprel: str | None = None          # head 为句内 token 序号，0 为根
@dataclass
class Sentence: start: int; end: int; tokens: list[Token]; external_id: str | None = None   # 句级对齐引用它
@dataclass
class Document: title: str; language: str; text: str; metadata: dict; sentences: list[Sentence]
                external_id: str | None = None                             # 如 Tatoeba 句 id
@dataclass
class Alignment: src_external_id: str; tgt_external_id: str                 # 句级对齐，平行格式产出

# engine/parsers/__init__.py
def parse(path: Path, *, language: str | None, metadata: dict) -> tuple[list[Document], list[Alignment]]
# 支持 txt、docx、csv、tsv、conllu、tmx、tatoeba；conllu 自带 tokens 时保留，其余留空待 nlp 填充

# engine/nlp.py
def annotate(doc: Document) -> None       # Stanza zh / en：分句、分词、pos、lemma、head、deprel；已有 tokens 的句子跳过

# engine/cwb.py
def build(index_dir: Path, corpus_key: str, documents: Iterable[Document], doc_ids: Iterable[str]) -> IndexInfo
#   位置属性 word pos lemma deprel head；结构属性 <doc id title lang 及元数据字段 meta_<key>> <s n>
#   元数据数值字段按零填充字串编码以支持范围比较；返回 tokens、sentences、documents 计数与 index_version
def search(index_dir: Path, corpus_key: str, cqp: str, *, restrict: str | None, sort: str, seed: int | None,
           page: int, page_size: int, context: Context, count_timeout: float = 20) -> SearchResult
#   restrict 为 CQP 全局约束表达式（由 subcorpus filter 编译）；SearchResult 字段与 HTTP 的 counts/items 对应，
#   items 用 doc id 与句内码点表示，api 负责补标题、元数据与对齐句
def context(index_dir: Path, corpus_key: str, doc_id: str, sentence_index: int, before: int, after: int) -> list[str]

# engine/query/__init__.py
def parse(text: str) -> QueryAST                      # 失败抛 QueryError(position, message)
def compile(ast: QueryAST) -> str                      # CQP；"+ / -" 同句条件编译为 within s 的 MU/meet 或 匹配后过滤
def compile_filter(filter: dict, fields: dict[str, str]) -> str   # subcorpus filter → restrict 表达式
```

查询语法以设计文档第五节为准：字串、`词/n`、相邻、`$N` 与 `$N-M`、`|`、`+`、`-`、引号精确、`*`、`?`；`{dep=}` 与 `[标签]` 在 P3 接入，P1 解析器须预留并返回"暂不支持"。中文字串查询按字符匹配并可跨词：编译为对 `word` 的正则序列或先在 token 层匹配再按码点校验，由 engine 决定，但命中必须返回精确码点区间。

## 四 数据库表（P1）

users、login_sessions、projects、project_members、corpora、documents、sentences、tokens、sentence_alignments、subcorpora、saved_queries、jobs。字段以第四节数据模型为准，由 api 的 Alembic 迁移定义，worker 复用同一模型。`tokens` 表只保存系统层（form、pos、lemma、head、deprel）；P3 的 annotation 表另加。

## 五 验收

- 内置 Tatoeba 中英、UD 中英各一份经导入与索引后状态 ready；统计数字与文件行数一致。
- 20 条金标查询（`tests/golden/p1-queries.json`）在 UD 英文上三项计数与人工核对一致。
- 上传 TXT 后在共享环境 1 分钟内 ready 并可查。
- 子库范围检索的文档数不超过子库文档数；范围筛选年份区间正确。
- 导出 CSV 行数等于命中数，XLSX 标题宋体、无底色。

## 六 实现定稿说明（2026 年 10 月 27 日）

以下为 P1 实现时确定的细节，以代码为准：

- 错误码补充：409 `CORPUS_NOT_READY`、`SEARCH_EXPIRED`（search_id 失效，前端去掉 search_id 重新检索）、`JOB_IN_PROGRESS`、`JOB_FINISHED`、`LAST_OWNER`；422 `QUERY_INVALID`、`INVALID_FILTER`、`UNSUPPORTED_FORMAT`；413 `TOO_LARGE`（上传上限 500 MB）；500 `INTERNAL`。`/search/parse` 对语法错误返回 200 且 `ok=false`。
- `search_id` 由 api 进程内缓存（上限 2000 条），固定随机种子与最终计数；翻页重跑 engine。
- `SavedQuery = {id, project_id, name, query, scope, created_at}`；导出任务 `result = {rows, hits, filename}`。
- 表 `sentences` 保存句文本，供上下文、对齐句与导出直接读取；文档全文在磁盘 `documents.text_path`。
- engine：`compile()` 返回多行引擎串（CQP 加 `+`/`-`/`#` 行），api 原样传给 `search`；`compile_filter` 数值范围用 CQP `int()`，数值零填充 12 位；中文字串按字符跨词匹配，上限 8 字；命中为每个起点一条、取最短匹配；非 CJK 字串按整词、不区分大小写；POS 接受 UPOS 或 CCL 短标签（n→NOUN|PROPN、v→VERB、a→ADJ…）；Tatoeba 以上传目录为 `parse()` 输入；计数超时后以 `cut` 返回当前页且 `complete=false`。
- 索引目录 `index_dir/registry/<key>` 与 `index_dir/<key>/<version>/`，重建后原子切换并删除旧版本；码点与文本来自 sidecar `offsets.bin`/`text.bin`，不受 CWB NFC 归一化影响。
- worker 单进程；启动时把残留 `running` 任务标为失败（`WORKER_RESTARTED`）；任务最终写入与成功标记在同一事务。
- 元数据字段仅当所有值均为 JSON 数值时视为 `number`，范围筛选只允许数值字段。

补充（2026 年 10 月 27 日，P2）：`SearchRequest.include_tokens?: bool`；为 true 时每个 `Hit` 附 `tokens: [{part: left|match|right, form, pos|null}]`（命中句的全部 token，按文档码点划分左、中、右），默认不返回。

补充（2026 年 10 月 27 日，jieba）：`engine.nlp.annotate` 对中文用 jieba（固定词典、HMM 关闭）分句、分词与词性（ICTCLAS 标签），lemma = form，导入时不做依存；英文仍用 Stanza。索引 `info.json` 记录 `tagset ∈ upos | jieba | mixed`（`cwb.tagset()`、`IndexInfo.tagset`），`query.parse(text, tagset)` 按标签集解析词性：jieba 语料上 `/n` 匹配 n 组全部子标签（n、nr、ns、nt、nz…），`/v` 匹配 v 组，精确子标签如 `/nr` 直接匹配；UPOS 名称在 jieba 语料上映射到对应字母组，`DET`、`AUX` 无对应报错；mixed 取并集。旧索引未重建前按 mixed 处理。非 UPOS 索引的 index_version 额外纳入 jieba 版本与词典哈希。

补充（P6，worker）：允许多个 worker；`jobs.heartbeat_at` / `worker_id`（迁移 0007），运行中每 30 秒心跳；启动与每 5 分钟的回收只把心跳超过 10 分钟（或无心跳且开始超过 24 小时）的 running 任务标为 `WORKER_RESTARTED`；`WORKER_KINDS` 限定可领取类型，`WORKER_HEAVY=0` 排除 import / index；Compose 另有 `worker-light` 只处理短任务，`--scale worker=N` 增加导入容量。

### 实现定稿说明（2026 年 10 月 28 日，用户文件导入）

- 列映射 `TableMapping = {text: [列] (1–2 个), title: 列|null, language: 列|null, metadata: [列]|null}`；`metadata` 为 null 时取除正文、标题、语言外的全部列。两列正文按 `text` 中的顺序以空行（两个换行符）连接（网页按表格列序提交），各列值去首尾空白，空值不参与；正文为空的行跳过，全部为空时 `PARSE_ERROR`「<文件> 正文列（…）没有内容」。映射中的列在文件里不存在时 `PARSE_ERROR`「<文件> 缺少列：…」。上传时 `mapping` 不合上述结构返回 422 `INVALID_MAPPING`。映射写入导入任务 `params.mapping`，任务重试与语料重试沿用。
- 未给映射时按默认值：正文 = 名为 text、content、body、sentence、abstract、正文、内容、句子 的第一列（不区分大小写，按此顺序），没有则取前 200 个数据行平均长度最长的列（排除标题列、语言列）；标题 = title、headline、标题；语言 = language、lang、语言。表头空名记为 `列N`，重名加 `_2`。标题截断到 500 字，为空时用「<文件名> #行号」。
- `TablePreview = {columns: [列], rows: [[值]] (前 5 个非空数据行), defaults: TableMapping}`；服务端最多读取 256 KB，读满时视为截断并丢弃最后一个不完整行；非 CSV/TSV 返回 422 `UNSUPPORTED_FORMAT`，无法解析返回 422 `PARSE_ERROR`。
- 文本编码（TXT、CSV/TSV、CoNLL-U）：UTF-8 BOM → UTF-16 BOM → 无 BOM 时前 4 KB 的零字节分布判为 UTF-16 LE/BE → 严格 UTF-8 → GB18030（含 GBK、GB2312）；都失败时 `PARSE_ERROR`「<文件> 无法识别编码（支持 UTF-8、GB18030/GBK、UTF-16）」。CRLF、CR 转为 LF，开头 BOM 去掉。CSV 单元格长度不设上限。
- 导入任务中解析器抛出的任何异常都记为 `PARSE_ERROR`，消息以文件名开头；自动标注不支持的语言记为 `ANNOTATE_ERROR`。已自带分词的文档（CoNLL-U）不再自动标注；英文 Stanza 标注把本批全部文档的段落合并按 200 段一批处理（`engine.nlp.annotate_many`），结果与逐篇处理一致。worker 以 `python -m services.worker.main` 启动时改为调用已导入的 `services.worker.main` 模块，修复任务抛出的 `JobFailed` 被当作 `INTERNAL` 的问题。

### 实现定稿说明（2026 年 10 月 28 日，语料库与任务队列）

- 上传 `language`：`auto` 表示每篇文档（CSV 每行，未映射语言列时）按正文判定语言（`engine.nlp.detect_language`），任务参数 `params.language` 记为 null；不传时仍用语料语言，语料语言为 `auto` 时同样逐篇判定。`POST /projects/{id}/corpora` 的 `language` 可为 `auto`，导入成功后语料语言改为文本量最大的语言代码。导入任务参数另记 `bytes`（本批文件总字节数）；导入完成触发的建索引任务参数记 `tokens`（语料词数）。
- 新增 `GET /corpora/{id}/documents/{doc_id}` → `Document`；`GET /corpora/{id}/documents/{doc_id}/sentences`（分页 `page`、`page_size` ≤ 200）→ 列表 `{id, idx, text, aligned: [{language, text}]}`，按句序；平行语料的 `aligned` 为两个方向对齐的句子，其他语料为空数组。
- `Corpus` 增加 `updating: bool`：状态为 ready / stale 且有排队或运行中的导入 / 建索引任务。已有索引（`index_version` 非空且状态 ready / stale）的语料上传或重建索引时状态不变，旧索引继续服务检索（不返回 `CORPUS_NOT_READY`）；新索引建好后替换。此时导入失败：状态不变、`error` 记原因；建索引失败或取消：状态改为 stale。没有索引的语料仍为 importing → indexing → ready，失败为 failed。
- `Corpus.meta` 在建索引时写入 `tagset`（upos | jieba | mixed，与 `cwb.tagset` 一致）、`script`（simplified | traditional | mixed，只有中文文档且对照字足够时出现）、`languages`（文档语言代码，按文本量降序）、`indexed_at`（ISO 时间）；`license`、`attribution`、`source_url`、`version` 不变。平行语料 `stats.pairs` = 源句属于该语料的句对数。
- DOCX 文档标题：第一个 Title 样式的非空段落 → 文档属性标题 → 第一个 Heading 1–9 段落 → 文件名。
- `Job.progress` 可带 `unit`（`个文件`、`字`、`篇`），`message` 为步骤名（解析 <文件>、分句与标注、写入、建索引）。`Job.queue_ahead`：排队中任务前面同一道（短任务 / 长任务，见 doc/deployment.md 队列规则）的运行中与更早排队任务数，其他状态为 null。worker 领取顺序：短任务先于长任务，再按创建时间；`WORKER_SMALL_IMPORTS=1` 的 worker（worker-light）在 `WORKER_KINDS` 之外也领取小导入与小语料建索引；同一语料已有运行中的建索引时不领取其另一个建索引任务。
