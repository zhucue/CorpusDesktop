# P2 接口契约：统计分析、Agent 服务与前端定稿

对应 [重构设计](../doc/platform-redesign.md) 第六、九、十一、十二节和 [前端整体设计方案](../doc/frontend-design.md)。延续 [P1 契约](p1.md) 的约定：`/api` 前缀、Cookie 会话、`{error: {code, message}}`、列表 `{items, total}`、唯一 `jobs` 表。

## 三 统计接口

统计一律为后台任务。`POST` 返回 `Job`（kind = stats，`result = {stat_id}`），完成后读取结果。

| 方法 路径 | 请求 | 响应 |
| --- | --- | --- |
| POST /stats/frequency | `{scope, unit: word\|lemma\|pos, pos?: string, top: 200, min_freq: 1}` | `Job` |
| POST /stats/ngrams | `{scope, n: 2\|3\|4, unit: word\|lemma, pos_pattern?: ["v","n"], top: 200, min_freq: 2}` | `Job` |
| POST /stats/collocations | `{scope, node: string(查询式), window: 5, unit: word\|lemma, pos?: string, measures: [mi, logdice, t, ll], min_freq: 3, top: 200}` | `Job` |
| POST /stats/keywords | `{target: scope, reference: scope, unit: word\|lemma, measure: ll\|log_ratio, min_freq: 3, top: 200}` | `Job` |
| POST /stats/distribution | `{scope, query?: string, field: string(元数据字段)\|"position", bins?: 10}` | `Job` |
| GET /stats/{stat_id} | — | `StatResult` |
| GET /projects/{id}/stats | — | 列表 `StatResult`（不含 rows） |
| POST /stats/{stat_id}/export | `{format: csv\|xlsx}` | `Job`（kind = export） |
| DELETE /stats/{stat_id} | — | 204 |

```text
scope = {corpus_id} | {subcorpus_id}
StatResult = {id, project_id, method, params, scope: {corpus_id, subcorpus_id|null, name},
              index_version, totals: {tokens, sentences, documents}, created_at,
              columns: [{key, label, type: string|number, unit?}], rows: [Row], row_count}
Row = {key: string, values: {...columns}, search_query: string|null, search_scope: scope}
```

| 方法 | 列 | search_query |
| --- | --- | --- |
| frequency | 项、频次、每百万词、文档频率 | `"项"`（词形）或 `/pos` |
| ngrams | n-gram、频次、每百万词 | 相邻词序列 `"w1" "w2"` |
| collocations | 搭配词、共现频次、搭配词频次、MI、logDice、t、LL | `节点 $window 搭配词`（双向窗口，后端生成等价查询式） |
| keywords | 词、目标频次、参照频次、目标每百万、参照每百万、LL、log ratio、显著性 | `"词"` 在目标范围 |
| distribution | 区间或字段值、命中数、词数、每百万 | 原 query 加该字段筛选的子库条件（返回 `search_scope` 为临时筛选 `{corpus_id, filter}`） |

统计单位与分母：每百万词以范围内 token 总数为分母；关键词参照库可为内置语料或任意子库；LL 与 log ratio 按标准公式，附 p 值阈值 0.05/0.01/0.001 的显著性标记。计算实现在 `engine/stats.py`，输入 CWB 索引目录与 scope 的 restrict 表达式（复用 `engine.query.compile_filter`）。

distribution 的 `search_scope.filter` 允许 `POST /search` 的 `scope` 接受第三种形式 `{corpus_id, filter}`（临时筛选，不保存）。

## 五 Agent 服务

### 身份与配置

- `POST /api/auth/agent-token {project_id}` → `{token, expires_at}`（30 分钟，存 `agent_tokens` 表或签名 JWT 二选一，实现方决定并写入本节）。api 的所有接口同时接受 `Authorization: Bearer <token>`，解析为该用户并限制在该项目。
- agent 服务环境变量：`MODEL_BASE_URL`、`MODEL_API_KEY`、`MODEL_ID`、`MODEL_API`（`openai-completions` | `openai-responses`，默认 completions）、`API_BASE_URL`（容器内 api 地址）、`DATABASE_URL`（写会话与消息）、`DATA_DIR`（Pi 会话文件）、`PORT`。
- 未配置模型时 `GET /agent/health` 返回 `{ok: false, reason: "MODEL_NOT_CONFIGURED"}`，前端禁用发送并提示。
- 向量与对话模型地址、密钥由用户提供，不入库。

### 会话接口（浏览器经 nginx `/agent/` 访问，携带 Cookie；agent 服务用 Cookie 调 api `/auth/me` 换取身份后再签发自己的 agent-token）

| 方法 路径 | 请求 | 响应 |
| --- | --- | --- |
| GET /agent/health | — | `{ok, model_id?, reason?}` |
| GET /agent/sessions?project_id= | — | 列表 `Session` |
| POST /agent/sessions | `{project_id, scope: {corpus_id}\|{subcorpus_id}\|null, title?}` | `Session` |
| GET /agent/sessions/{id} | — | `Session + messages: [Message]` |
| PATCH /agent/sessions/{id} | `{title?, scope?}` | `Session` |
| DELETE /agent/sessions/{id} | — | 204 |
| POST /agent/sessions/{id}/messages | `{content}` | SSE 事件流 |
| POST /agent/sessions/{id}/cancel | — | 204 |

```text
Session = {id, project_id, owner_id, title, scope, state: idle|running, created_at, updated_at, message_count}
Message = {id, role: user|assistant, content: string, parts: [Part], tool_calls: [ToolCall], created_at, duration_ms?}
Part = {type: text, text} | {type: ui, lang: string(OpenUI Lang 文本)} | {type: thinking, text}
ToolCall = {id, name, args, state: running|succeeded|failed|cancelled, result_summary: string, result_ref?: {kind, id}, duration_ms}
```

SSE 事件（`event:` 名 + JSON `data:`）：

| 事件 | data | 说明 |
| --- | --- | --- |
| start | `{message_id}` | 助手消息开始 |
| thinking | `{delta}` | 推理文字增量（模型支持时） |
| tool_call | `ToolCall`（state=running） | 工具开始 |
| tool_result | `ToolCall`（终态） | 工具结束 |
| text | `{delta}` | 回答文字增量 |
| ui | `{delta}` | OpenUI Lang 增量，前端流式渲染 |
| done | `{message: Message}` | 完整消息（已持久化） |
| error | `{code, message}` | 终止；code 同 api 错误码或 MODEL_* |

同一会话同时只允许一个运行；再次发送返回 409 `SESSION_BUSY`。断线重连读取 `GET /agent/sessions/{id}`，运行中的消息以 `state=running` 的 ToolCall 展示；不做跨进程接续。工具等待后台任务最长 90 秒，超时返回 `{job_id}` 并提示用户到任务页查看。

## 九 实现定稿说明（后端，2026 年 10 月 27 日）

- agent-token：32 字节随机串，`agent_tokens` 表存 SHA-256，30 分钟有效；Bearer 请求限制在该项目，不能创建项目、内置语料或新 token，跳过 Origin 检查；签发接口本身需 Cookie 会话且带匹配的 Origin。
- 统计任务先校验（422 `QUERY_INVALID` / `INVALID_FIELD` / `VALIDATION_ERROR`、409 `CORPUS_NOT_READY`）再入队；成功 `job.result = {stat_id}`；内置语料范围需 `project_id`（Bearer 时取自 token），否则 422 `PROJECT_REQUIRED`。
- 搭配行有 `search_query`（右侧 `节点 $K "搭配词"`）与 `search_query_reverse`（左侧）；词元行用该词元在范围内的词形并列表示，含引号的词形 `search_query` 为 null。
- `totals` 附加：搭配 `node_hits`、`window_tokens`；关键词 `reference`；分布 `hits`。分布无 query 时 `hits`、`per_million` 为 null；缺字段文档不计；位置区间标签如 `0–10%`。
- `{corpus_id, filter}` 范围在检索、导出、保存查询、统计中通用；与 `subcorpus_id` 同时出现返回 422。
- 证据篮权限：owner / editor / annotator 可钉住，viewer 只读与导出，删除需 owner / editor 或创建者。
- 计数来自 `cwb-scan-corpus`（范围由 restrict 表达式给出），n-gram 不跨句；搭配窗口 ±N 句内、并集计一次；关键词 LL 按 Rayson、log ratio 按 Hardie（零频计 0.5），只列目标库相对更频繁的词；显著性阈值 3.84 / 6.63 / 10.83。
- agent 服务容器：`DATABASE_URL` 为纯 `postgresql://` 串，`DATA_DIR=/data/agent`（独立卷），`PORT=8700`，`API_BASE_URL=http://api:8000/api`；nginx 对 `/agent/` 关闭缓冲、超时 600 秒。

## 十 实现定稿说明（Agent 服务，2026 年 10 月 27 日）

- OpenUI 采用官方 `@openuidev/lang-core`（服务端目录与提示生成）和 `@openuidev/react-lang`（前端渲染），不使用 JSON 退路。模型在正文中输出 ```openui-lang 围栏块，每块是以 `root = 组件名(...)` 为入口的完整程序，参数按位置对应 `services/agent/src/components.ts` 的 schema；服务端去掉围栏，正文走 `text` 事件，代码走 `ui` 事件。
- `thinking` / `text` / `ui` 事件 data 为 `{delta, part}`，`part` 为 `message.parts` 下标；新围栏或新回合开新 part。
- 取消以正常 `done` 结束（部分消息持久化，运行中的 ToolCall 置 `cancelled`）；模型错误在 `start` 后发 `error`，code 为 `MODEL_NOT_CONFIGURED`（POST 返回 503）、`MODEL_AUTH_FAILED`、`MODEL_RATE_LIMITED`、`MODEL_TIMEOUT`、`MODEL_REQUEST_FAILED`；运行中的会话 DELETE 返回 409 `SESSION_BUSY`；浏览器断开不终止运行，进程重启后未完成的 ToolCall 读取时显示 `cancelled`。
- Pi 工具名用下划线（`corpus_search`），ToolCall.name 保留点号名；`result_ref.kind` ∈ search / stat / job / evidence / corpus / subcorpus / query。统计工具返回前 50 行且不带 `search_query`；`corpus.context` 入参 `{hit_id, sentence_index}`；`export.create` 入参 `{target: search|stat, format, ...}`。
- 组件行结构：CollocationTable `{collocate, freq, score}`，KeywordTable `{word, target_freq, reference_freq, score}`，JobStatus progress `{done, total|null, message}`。
- 可选环境变量：`MODEL_CONTEXT_WINDOW`（128000）、`MODEL_MAX_TOKENS`（8192）、`MODEL_TIMEOUT_MS`（120000）、`MODEL_REASONING`、`PUBLIC_ORIGIN`（设置后对自身非 GET 路由做 Origin 校验）。SSE 每 15 秒发 `: ping`。
- Pi 会话文件在 `DATA_DIR/sessions/<session_id>/`，以 `SessionManager.continueRecent` 续接；服务启动时把残留 `running` 会话置 `idle`。

## 十一 实现定稿说明（前端，2026 年 10 月 27 日）

- `SearchRequest.include_tokens?: bool`；为 true 时 `Hit.tokens = [{part: left|match|right, form, pos}]`，供词性着色。
- 前端 `UiBlock` 先尝试 JSON `{component, props}`，否则交给 `@openuidev/react-lang`；组件库与 `services/agent/src/components.ts` 同名同参数顺序，无 root。
- 分类色板 c5 改为青色 `#479CA6`；柱状图与进度线纯色。
- 统计页"统计结果"抽屉列出项目内所有结果（`GET /projects/{id}/stats`）；助手卡片中 CollocationTable 行自行拼 `节点 $N "搭配词"` 打开检索，KwicTable 在会话范围内重跑查询。
- 补充（联调后）：agent 容器环境加 `PUBLIC_ORIGIN`，用于其自身非 GET 路由的 Origin 校验。搭配表的"共现频次"按窗口内每个搭配词位置计一次，与"回到例句"查询（`节点 $K "搭配词"` 单侧）的命中数不是同一口径，界面以列标题区分。
- 补充（jieba）：统计与检索的词性校验按语料库标签集进行，语料未就绪时先返回 409 再谈 422；词性单位的频次行中，jieba 字母组标签（n、v…）的 `search_query` 为 null，子标签与 UPOS 行正常。
- 补充（P6-3）：Bearer 不能增删改项目成员（仅人工）；被移出项目的成员对自己任务、导出与 Agent 会话的访问立即失效（404）。
- 补充（P6）：Bearer 不能删除语料、文档、子库、保存的查询、统计和证据（含 agent 自己钉住的），也不能上传项目语料或重建索引（403）。任务由创建者（任何角色）或 owner / editor 取消、重试。`Job` 增加 `owner_id`、`owner_email`、`summary`。`GET /jobs?builtin=1` 仅平台管理员（Cookie）可用，返回 project_id 为 null 的任务；缺 builtin=1 返回 422。环境变量 `SEARCH_COUNT_TIMEOUT`（默认 20 秒）。
