# P4 接口契约：知识库

对应 [重构设计](../doc/platform-redesign.md) 第八节与第十二节 P4，[前端整体设计方案](../doc/frontend-design.md) 知识库页。延续 P1–P3 约定。

## 一 范围

| 模块 | 内容 |
| --- | --- |
| 文献 | PDF / DOCX / Markdown / TXT 上传与网页 URL 导入；解析、分段、向量化；出处（页码或标题路径） |
| 术语表 | 手工录入；从双语语料和文献抽取候选；译名、定义、领域、语料例句；草稿与确认 |
| 标注规范 | Markdown 文档，关联标签集；预标提示词引用 |
| 研究笔记 | Markdown 笔记；引用检索、统计、证据、知识片段；证据篮"加入笔记"、助手"保存为笔记"落地 |
| 检索 | 混合检索（向量 + 关键词）返回片段与出处 |
| Agent | kb.search、kb.save、kb.extract_terms、kb.summarize；组件 TermCard、KbCitation |
| 导出 | 术语 CSV / XLSX / TBX；笔记 DOCX / Markdown |

## 二 向量模型

- 默认本地：`sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`（384 维，中英通用，CPU 可用），随 worker 镜像按固定版本下载到 `models` 卷；`pipelines/alignment/` 的旧实验用过同类模型，P5 对齐复用。
- 可选远程：`EMBED_PROVIDER=openai`、`EMBED_BASE_URL`、`EMBED_API_KEY`、`EMBED_MODEL`、`EMBED_DIM`，走 OpenAI 兼容 `/embeddings`。
- 向量维度写入 `kb_chunks.embedding` 列定义（pgvector `vector(384)`，远程模型不同维度时迁移另建列）；每个片段记录 `embed_model`，模型变更时整库重算为后台任务。

## 三 数据模型（迁移 0004）

| 表 | 字段 |
| --- | --- |
| kb_documents | id、project_id、kind: literature|guideline|note|url、title、source（文件名或 URL）、file_path|null、text_path、body（note / guideline 的 Markdown 正文）、meta JSONB（作者、年份、页数、label_set_id…）、status: queued|parsing|embedding|ready|failed、error、chunk_count、created_by、created_at、updated_at |
| kb_chunks | id、document_id、ordinal、text、locator JSONB（`{page}` 或 `{heading_path}` 或 `{line}`）、embedding vector(384)、embed_model、tsv（PostgreSQL 全文列，中文按 jieba 分词后以空格连接写入） |
| kb_terms | id、project_id、term、language、translations JSONB `[{language, text}]`、definition、domain、examples JSONB `[{text, source, hit_id?, document_id?, start_cp?, end_cp?}]`、source: manual|corpus|literature|model、status: draft|confirmed、created_by、confirmed_by|null、created_at、updated_at；唯一 (project_id, term, language) |
| note_refs | note_id、kind: search|stat|evidence|chunk|term、ref JSONB、created_at（笔记引用，便于反查） |

## 四 HTTP 接口

### 文献与文档

| 方法 路径 | 请求 | 响应 |
| --- | --- | --- |
| GET /projects/{id}/kb/documents?kind=&q= | — | 列表 `KbDocument`（不含正文） |
| POST /projects/{id}/kb/documents | multipart：`files`（pdf / docx / md / txt，≤ 50 MB）或 JSON `{url}` 或 `{kind: note|guideline, title, body, meta?}` | `KbDocument`（文件与 URL 自动建 `Job` kind = kb_import，`job_id`） |
| GET /kb/documents/{id} | — | `KbDocument + body`（note / guideline）或 `+ text_preview` |
| PATCH /kb/documents/{id} | `{title?, body?, meta?}` | `KbDocument`（note 正文修改即保存，无版本） |
| DELETE /kb/documents/{id} | — | 204 |
| POST /kb/documents/{id}/reimport | — | `Job` |
| GET /kb/documents/{id}/chunks?page= | — | 列表 `Chunk` |
| POST /kb/documents/{id}/summarize | — | `Job`（kind = kb_summarize，结果写 `meta.summary`，status 草稿标记 `meta.summary_source = model`） |

```text
KbDocument = {id, project_id, kind, title, source, meta, status, error|null, chunk_count, created_by, created_at, updated_at}
Chunk = {id, document_id, ordinal, text, locator, score?}
```

导入任务：解析（pdf → pypdf 按页；docx → python-docx 段落与标题层级；md / txt → 标题与段落；url → trafilatura 正文）→ 分段（约 500 字符，重叠 80，不跨标题）→ 向量化（批 64）→ ready。失败保留错误原因，可重导。

### 术语

| 方法 路径 | 请求 | 响应 |
| --- | --- | --- |
| GET /projects/{id}/kb/terms?q=&status=&language= | — | 列表 `Term` |
| POST /projects/{id}/kb/terms | `Term` 字段子集 | `Term` |
| PATCH /kb/terms/{id} | 任意字段；`{status: confirmed}` 记录 confirmed_by | `Term` |
| DELETE /kb/terms/{id} | — | 204 |
| POST /projects/{id}/kb/terms/extract | `{source: corpus, scope, method: pos_pattern|model, top: 100}` 或 `{source: literature, document_ids, method: model}` | `Job`（kind = kb_extract；结果为 draft 术语，`job.result = {created, skipped}`） |
| POST /kb/terms/{id}/examples | `{hit_id, document_id, start_cp, end_cp, text, source}` | `Term` |
| POST /projects/{id}/kb/terms/export | `{format: csv|xlsx|tbx}` | `Job` |

抽取方法：`pos_pattern` 在语料上按词性模式（中文 n+n / a+n / v+n，英文 ADJ+NOUN / NOUN+NOUN）统计候选，取频次与 logDice 排序前 top；双语语料附对齐句中对应候选译名（按共现频次）；`model` 把候选或文献片段交给对话模型，返回术语、译名、定义草稿，source = model。

### 检索

| 方法 路径 | 请求 | 响应 |
| --- | --- | --- |
| POST /projects/{id}/kb/search | `{q, kinds?: [literature|guideline|note|url], document_ids?, top_k: 8, mode: hybrid|vector|keyword}` | `{items: [{chunk: Chunk, document: {id, title, kind, source}, score, highlight}], terms: [Term]}` |

混合检索：向量余弦前 50 ∪ 关键词（`tsv @@ plainto_tsquery`，中文查询同样 jieba 分词）前 50，按 Reciprocal Rank Fusion 合并取 top_k；`terms` 为术语表精确或前缀匹配前 5。`highlight` 为关键词命中片段。

### 笔记引用

- `POST /kb/documents/{note_id}/refs {kind, ref}` 追加引用并返回；证据篮"加入笔记"把证据正文追加到笔记末尾并建 ref；助手"保存为笔记"创建 note（标题取会话标题，正文为该条回答 Markdown，ui 块转为文字表格或链接）。
- `POST /kb/documents/{id}/export {format: docx|md}` → `Job`（DOCX 宋体无底色，引用附出处）。

## 五 Agent

| 工具 | 说明 |
| --- | --- |
| kb.search | 混合检索，返回片段（≤ 8，每条 ≤ 600 字）、出处、术语 |
| kb.save | 创建或追加笔记：`{title?, note_id?, body, refs?}` |
| kb.extract_terms | 发起抽取任务并等待（≤ 90 s），返回前 20 条草稿 |
| kb.summarize | 对文档发起摘要任务并等待 |
| kb.terms | 查术语 |
| kb.documents | 列文档 |

系统提示：回答涉及知识库内容时必须引用 KbCitation 并给出 document_id / chunk_id；术语建议只能是 draft；规范文档可作为预标提示的依据（P5）。

组件：`TermCard(term_id, term, translations: [{language, text}], definition, domain, examples: [{text, source}], status)`；`KbCitation(items: [{chunk_id, document_id, title, locator, text}])`。

## 六 前端

- 知识库页四个标签：文献（列表、上传/URL 导入、状态、片段预览、摘要）、术语（表格、筛选 draft/confirmed、术语卡、抽取对话框、导出）、规范（Markdown 编辑，关联标签集）、笔记（左列表右编辑器，Markdown，引用面板，导出）。
- 顶部检索框：混合检索结果列表，片段高亮，出处可点开文档位置；术语匹配单独一行。
- 证据篮"加入笔记"选择或新建笔记；助手卡片"保存为笔记"；检索页 KWIC 行"加入术语例句"。
- 引导页"完成"步骤加知识库入口；命令面板加文献/术语搜索。

## 七 验收

- 导入 10 篇 PDF（含中英文）后全部 ready；`kb.search` 问题答案带 KbCitation 且出处页码正确（抽样 10 条人工核对）。
- 从 Tatoeba 中英子库按 pos_pattern 抽取术语 ≥ 50 条草稿，含译名；确认 10 条后可导出 TBX 并通过 XML 校验。
- 笔记引用检索与统计后导出 DOCX，含原文、出处与查询式。
- 混合检索对中文和英文查询都能返回关键词命中片段；向量模型未就绪时降级为关键词检索并提示。
