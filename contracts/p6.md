# P6 收尾计划与验收

对应 [重构设计](../doc/platform-redesign.md) 第十二节 P6。P6 不新增业务接口，内容为内置语料、完成度审查、回归、性能基线、部署与文档。

## 一 任务

| 编号 | 任务 | 交付 |
| --- | --- | --- |
| P6-1 | 前端完成度专项审查 | 对照《前端整体设计方案》、`doc/ui-design/` 与 contracts/p1–p5，逐页逐状态（正常 / 空 / 处理中 / 失败）、逐功能核对；输出差距清单（严重 / 一般 / 细节）并修复严重与一般项；深色模式、键盘可达、错误展示、reduced-motion 复查 |
| P6-2 | 内置语料 | 管理员用 `POST /corpora` 建内置语料并导入：Tatoeba 中英完整直接句对（官方三件 tsv，`scripts/import_tatoeba.py` 调用现有导入，含许可与署名元数据）、UD 英文 EWT 与 UD 中文 GSD（CoNLL-U，许可元数据）、维基中英子集（各 1000 篇，`scripts/import_wiki_subset.py` 从官方 dump 抽样清洗，记录许可）；内置语料页面：管理员可上传、重建索引，普通用户只读；语料详情显示许可与署名，导出带署名 |
| P6-3 | 权限与撤销回归 | 脚本化矩阵：owner / editor / annotator / viewer / 非成员 / 管理员 / Bearer 对全部写接口的允许与拒绝；成员被移除后其 Cookie 会话与 agent-token 立即失效；删除语料后检索、统计、标注层、证据、笔记引用的表现 |
| P6-4 | 性能基线 | 在完整 Tatoeba 中英（约 210 万句、2000 万词）上记录：导入与索引耗时、字串 / 词 / 词性 / 属性查询首屏与完整计数、五种统计耗时、混合检索延迟；形成 `doc/performance.md` 表格与复跑脚本 `scripts/bench.py`；超过 20 秒的操作确认有进度与"计算中"表现 |
| P6-5 | 备份与恢复 | `scripts/backup.sh` / `restore.sh`：PostgreSQL dump + 数据卷（语料文件、索引、知识库文件、Pi 会话、模型缓存可不备）；恢复后抽查检索、标注、知识库；写入部署文档 |
| P6-6 | 部署文档 | `doc/deployment.md`（+ Word）：环境要求、`.env` 全部变量说明、首次启动顺序、模型配置（对话与向量）、端口与反代、升级（迁移）、备份恢复、常见故障（模型未配置、向量未就绪、端口占用、维基 403） |
| P6-7 | README 与文档收口 | README 更新为最终定位、功能清单、启动与开发命令、文档入口；重构设计第十二节进度全部更新；change-log 收口；所有 Word 重新生成 |
| P6-8 | 两条研究流程端到端验收 | 干净环境（新卷）Compose 启动 → 建账号 → 流程 1 翻译研究：Tatoeba 中英子库检索"翻译"、看对齐句、统计译法频次（关键词 + 搭配）、抽取术语入知识库、助手生成笔记草稿、导出 DOCX；流程 2 学习者语料：上传作文 TXT、预标词性依存、learner-errors 片段标注、偏误分布统计、与参照库关键词比较、导出 brat 与 XLSX。每步截图与耗时记录在 `doc/acceptance.md` |

## 二 顺序

P6-1 与 P6-2 并行先做（审查结果可能改前端；内置语料是流程验收的前提）；随后 P6-3、P6-4、P6-5 并行；最后 P6-6、P6-7、P6-8。

## 三 验收

- 审查清单中严重与一般项全部修复，细节项列入二期。
- 四类内置语料 ready，许可与署名在页面与导出中可见。
- 权限矩阵脚本全部通过；撤权即时生效。
- 性能表格完整，首屏查询在完整 Tatoeba 上 P95 ≤ 3 秒（共享环境记录实际值，不达标时写明）。
- 恢复演练通过。
- 干净环境两条流程走通，`doc/acceptance.md` 有截图与耗时。

## 四 实现说明（P6-2 内置语料、P6-4 性能基线）

- 语料来源与许可：迁移 0006 给 `corpora` 增加 `metadata` JSONB（默认 `{}`）。`POST /corpora`、`POST /projects/{id}/corpora` 接受可选 `meta: {license?, attribution?, source_url?, version?}`（各字段字符串，长度上限 200 / 2000 / 1000 / 200）；`Corpus` 视图增加 `meta`（无数据时为 `{}`）。
- 导出署名：语料带 `license` 或 `attribution` 时，检索导出与统计导出（关键词另含参照语料）在表格上方写一行"来源：名称；许可：…；署名：…；链接：…；版本：…"，再空一行接表头（CSV、XLSX）；DOCX 写在标题下；标注层 CoNLL-U 导出以 `# 来源：…` 注释行开头。无许可信息的语料导出不变。
- 脚本：`scripts/import_builtin.py`（子命令 `tatoeba`、`ud --treebank en_ewt|zh_gsd`、`wiki --lang zh|en --n 1000`）替代计划中的 `import_tatoeba.py` 与 `import_wiki_subset.py`；`scripts/bench.py` 生成 `doc/performance.md`。
- Tatoeba 分批：完整中英约 213 万句，按"链接连通分量不拆分"切成 8 批上传，每批 cmn / eng 两个文档（元数据 `part`），对齐全部落在同一批内；脚本等上一批导入完成再传下一批，其他用户的任务可在其间执行。
- worker：导入标注进度按字符计（消息"标注（字符）"），大文档内部也推进并可取消；句与词按 5000 句一轮写入；建索引按"最多 500 文档且 100 万词"一轮从数据库读取，超过 100 万词的文档单独一轮，读取用元组不用 ORM 对象。
- 标注层导出署名：brat 在 `annotation.conf` 开头写 `# 来源：…` 并附 `README.txt`；JSON 顶层 `source` 数组；TMX `<header>` 内 `<note>`（含源与目标语料）；XLSX 两个 sheet 首行为来源行后空一行。
