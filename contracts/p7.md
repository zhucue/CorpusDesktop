# P7 批次 1：正确性与上线前

来源：[调研报告](../doc/reviews/2026-11-05-gap-research.md) 第四节批次 1（H1、H3、H4、M12、C1–C5、C12）。不新增研究功能；修正计数与翻页、误删提示、助手上下文、证据篮清空，补账号生命周期、数据去向说明与健康检查。

## 一 检索计数、翻页与排序（H1）

现状：`POST /search` 每次（含翻页、带 `search_id` 重取计数）都重跑整条 CQP；超过 `COUNT_TIMEOUT`（20 秒）时只取前 page×page_size 条，并在其中排序，翻页重复或漏行；计数永远完成不了。

规则：

- **完整结果算一次。** 首次检索在 20 秒内完成：照旧返回首页与完整计数，同时把完整命中行（过滤、排序之后的行，足以重建任一页）存为该 `search_id` 的结果集。之后带 `search_id` 的翻页直接从结果集切片，不再跑 CQP。
- **超时转后台。** 首次检索超时：照旧返回语料顺序的首页、`counts.complete=false`，并为该 `search_id` 启动一次后台完整计数（同一 `search_id` 只启动一次）。后台使用更长超时 `SEARCH_FULL_TIMEOUT`（默认 300 秒），完成后写入计数与结果集。带 `search_id` 的轮询只读状态，不重跑。
- **后台失败或超长。** 超过 `SEARCH_FULL_TIMEOUT` 或出错时，计数状态为失败：`counts = {hits:null, sentences:null, documents:null, complete:false, failed:true, message}`。`message` 为固定文案，不含内部错误：超时为"计数超时（300 秒），请缩小范围或加条件"；命中超过上限为命中过多、请缩小范围；被同一用户同一登录方式的新检索取消时为"计数已取消：已开始新的检索"；其他错误为计数失败、请重试。前端显示 `message`，不再轮询。
- **命中上限。** 一次检索的命中数超过 `SEARCH_MAX_HITS`（默认 2,000,000）时后台计数按失败处理（命中过多），不写结果集。
- **未完成时的排序。** 计数未完成前，`sort=left|right|random` 的页按语料顺序返回，响应 `sort_applied:false`；前端在结果栏显示"排序在计数完成后生效"。完成后自动按所选排序重取当前页。`sort=position` 未完成时翻页按语料顺序切片，与完成后的结果一致。
- **并发与资源。** 后台完整计数全进程最多 2 个同时运行，其余排队；同一用户同一认证方式（浏览器会话、助手 Bearer 令牌各算一种）同时最多 1 个，新的会取消该用户在同一认证方式下上一个未完成的后台计数；助手与浏览器互不取消。结果集存 `DATA_DIR/search-cache/<search_id>`（或等价磁盘位置，不放内存），随 `SearchCache` LRU（现 2000 条）淘汰时删文件；全部结果集总字节不超过 `SEARCH_CACHE_MAX_BYTES`（默认 2 GB），超出时按最近最少使用淘汰。api 进程启动时清空该目录。缓存键不变（语料、`index_version`、范围、cqp、层、排序）；索引版本变化时旧 `search_id` 返回 409 `SEARCH_EXPIRED`（现有行为）。
- **适用范围。** 本条只改 CWB 路径（`engine/cwb.py` 与 `services/api/search.py` 的 `run_search`）。纯属性查询与纯片段查询走 PostgreSQL 的路径（`effective.py`）本批不改（M1 在批次 3）。
- 检索导出（`services/worker/tasks.py`）不在本批改动范围，但不得因本条改动失效。

接口变化（向后兼容，字段新增）：

```text
SearchResult += {sort_applied: bool}
counts += {failed?: bool, message?: string}
```

验收：构造超过 20 秒的查询（可用测试钩子把 `COUNT_TIMEOUT` 调小）：首屏返回、后台完成后计数准确且与独立 CQP 计数一致；完成后第 1–5 页拼接无重复无遗漏，与一次性全量结果逐行一致；left / right / random 在完成前返回 `sort_applied:false`，完成后排序正确且翻页稳定；轮询期间 CQP 只被调用一次（测试计数）。

## 二 删除语料与文档的影响提示（H3）

- 新增 `GET /corpora/{id}/delete-impact` 与 `GET /documents/{id}/delete-impact`，权限同删除。响应 `{documents, sentences, layers: [{id, name, kind, human: int}], human_annotations, evidence, kb_refs}`：`human` 为该层中人工处理过的条目数，即 status 为 `confirmed`、`modified`、`rejected` 的条目（片段、关系、对齐、词性依存校对均计；`suggested` 不计），`human_annotations` 为各层之和，`evidence` 为引用这些句子的证据条数，`kb_refs` 为引用它们的笔记引用条数。
- 前端删除确认框列出：将删除的文档数；标注层名与各层人工条目数；证据与笔记引用条数。`human_annotations > 0` 时，确认按钮在勾选"我确认删除这些人工标注"后才可用。无影响时保持原确认框。
- 不改级联行为；证据与笔记引用不随之删除，删除后无法回到原句（确认框写明）。软删除在批次 3。

## 三 助手抽屉上下文（H4）

- `POST /sessions/{id}/messages`（agent 服务）接受可选 `context`：

```text
context = {page: "search"|"stats"|"annotate"|"knowledge"|"corpora", label: string,
           query?: string, search_id?: string, hit_ids?: string[] (≤ 20), scope: Scope}
```

- agent 在本轮用户消息前附加一段不显示给用户的上下文（例："[当前页面：检索] 查询式：翻译/v；范围：Tatoeba 中英 · 中文侧；选中命中：…"），模型据此调用工具；会话存储中用户消息仍只显示用户输入，上下文另存在该消息的 `context` 字段，供回放核对。
- 检索页打开抽屉时传当前查询式、`search_id` 与选中的命中（无选中则不传 `hit_ids`）；其他页面只传 page、label、scope。
- 会话的 scope 与当前页面 scope 不同时，抽屉顶部显示一行"会话范围：A；当前页面：B"和按钮"按当前范围新对话"。不自动切换。
- 抽屉文案"针对当前结果"仅在实际传了 `query` 时显示，否则显示范围名。

## 五 账号生命周期（C1、C2）

数据：迁移 `0008_account_lifecycle`：`users.disabled_at timestamptz null`，`users.must_change_password bool default false`，`users.last_login_at timestamptz null`。

| 方法 路径 | 权限 | 说明 |
| --- | --- | --- |
| GET /admin/users | 管理员 | `{items, total}`；`AdminUser = {id, email, display_name, is_admin, disabled_at, last_login_at, created_at, projects: int}`；支持 `q`（邮箱或姓名包含） |
| POST /admin/users | 管理员 | `{email, display_name, is_admin?}` → `{user: AdminUser, temporary_password}`；临时密码 16 位随机，只返回这一次；`must_change_password=true` |
| POST /admin/users/{id}/reset-password | 管理员 | → `{temporary_password}`；`must_change_password=true`；吊销该用户全部会话与 agent 令牌 |
| POST /admin/users/{id}/disable | 管理员 | 设 `disabled_at`；吊销全部会话与 agent 令牌；不能停用自己；不能停用最后一个未停用的管理员 |
| POST /admin/users/{id}/enable | 管理员 | 清 `disabled_at` |
| POST /admin/users/{id}/admin | 管理员 | `{is_admin: bool}`；不能撤销最后一个未停用的管理员 |
| POST /auth/password | 本人，浏览器会话（Bearer 拒绝） | `{old_password, new_password}`；新密码 12–1024 字符且不同于旧密码；成功后清 `must_change_password`，吊销本人其他会话与 agent 令牌，保留当前会话 |

- 登录：停用账号返回 403 `ACCOUNT_DISABLED`"账号已停用，请联系管理员"；成功时写 `last_login_at`。`current_user` 与 agent 令牌校验同样拒绝停用账号（已存在的会话立即失效）。
- `GET /auth/me` 增加 `must_change_password`。为 true 时前端只允许进入改密码页（登录后直接跳转）；后端除 `/auth/me`、`/auth/password`、`/auth/logout` 外返回 403 `PASSWORD_CHANGE_REQUIRED`。
- 登录限流沿用现有规则；`/auth/password` 旧密码错误计入同一限流。
- `scripts/create_account.py` 增加 `--reset`：账号存在时重置密码（从 stdin 读或生成并打印），设 `must_change_password=true`，吊销会话。
- 前端：设置页增加"修改密码"；管理员在设置页看到"用户"标签：列表（邮箱、姓名、管理员、状态、最近登录、项目数）、搜索、新建（显示一次临时密码，可复制）、重置密码、停用 / 启用、设为 / 取消管理员。危险操作二次确认。

## 六 数据去向与系统信息（C4、C12）

- `GET /api/health`：执行 `SELECT 1`；成功 `200 {ok: true, db: true}`，失败 `503 {ok: false, db: false}`。compose 的 api 健康检查继续用它。
- worker 与 worker-light 每轮主循环（含空闲轮询）更新 `DATA_DIR/worker-health/<WORKER_ID>` 文件的修改时间；compose 为两者加健康检查：该文件 90 秒内更新过。
- `GET /system/info`（登录即可）：`{version, model: {configured: bool, host: string|null, model_id: string|null}, embed: {mode: "local"|"remote", host: string|null, model: string|null, ready: bool}}`。`host` 只给主机名，不给路径与密钥。`version` 读环境变量 `APP_VERSION`（默认 `dev`）。
- 前端：设置页"数据与隐私"区块：数据存放位置（本机 PostgreSQL 与数据卷）；管理员可见范围（管理员可查看全部用户与项目列表；不通过界面读取他人项目内容）；会把文本发给外部模型的操作——助手对话、LLM 片段预标、对齐候选（若用模型）、文献摘要、术语抽取——以及当前模型主机；备份保留由部署方决定。LLM 预标对话框与文献摘要、术语抽取的确认处各写一行"将把所选句子发送到 {host}"（未配置模型时按现有不可用状态）。
- 部署手册：上线检查清单补"在模型服务商侧设消费上限""备份复制到另一台机器""`chmod 600 deploy/.env`"；新增 `scripts/healthcheck.sh`：检查 `/api/health`、三个容器健康状态、数据盘剩余 < 10%、最近备份超过 26 小时，任一失败时 POST 到 `ALERT_WEBHOOK_URL`（未设则只打印并以非零退出），说明用 cron 每 5 分钟执行。

## 十 实现说明（2026 年 11 月 5 日）

与上文原文的差异，以实现为准：

- 第一节：后台计数取消范围按"用户 + 认证方式"区分，助手 Bearer 与浏览器会话互不取消（原文为同一用户 1 个）；补命中上限 `SEARCH_MAX_HITS`、结果集字节上限 `SEARCH_CACHE_MAX_BYTES` 与固定失败文案。前端不再有"继续计数"按钮与 1 分钟轮询上限，持续轮询到完成或失败。
- 第二节：`human` 口径写明为 confirmed / modified / rejected（被人工拒绝的建议也算人工结果）。
- 第五节：停用账号已有会话下一次请求返回 401 `ACCOUNT_DISABLED`（登录时为 403）；不能停用或撤销最后一个可用管理员时返回 409 `LAST_ADMIN`；`/admin/*` 只接受管理员浏览器会话，Bearer 403。agent 服务对 `must_change_password` 同样返回 403 `PASSWORD_CHANGE_REQUIRED`。`/auth/password` 在 nginx 与登录共用限流区。
- 第六节：`GET /system/info` 的模型信息由 api 读 `MODEL_BASE_URL`、`MODEL_ID`（只用于显示）。设置页标签为 项目 / 账号 / 数据与隐私 / 用户，原"模型配置"不做在线配置。发送说明按操作区分：LLM 预标"所选句子"，文献摘要"文献文本"，术语抽取按来源"文献文本"或"候选术语列表"。worker 健康文件在每轮主循环和任务心跳时更新。
- 第九节：权限矩阵测试给每个测试客户端设不同 `X-Forwarded-For`，避免触发登录限流。
