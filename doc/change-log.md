# 变更原因日志

从 2026 年 10 月 15 日开始记录，首批补记本轮已知变更。后续按日期追加，记录改动和原因。

## 2026 年 10 月 15 日

- 将正式 Word 和 Markdown 维护源统一到 `doc/`，旧版归入 `doc/history/`。原因：资料原先分散在 `docs/` 和 `output/`，需要让后续开发能直接找到当前基线。入口见 [README](../README.md)。
- 补齐[前端与接口规范](frontend-specification.md)，并生成对应 Word。原因：已有业务和技术架构尚不足以直接开发页面，需要明确页面流程、交互状态和接口契约。
- 统一 Pi 会话的研究范围：创建时绑定范围，切换快照或材料范围新建会话，不带入旧消息与工具摘要；范围不符返回 `409 SESSION_SCOPE_CHANGED`。原因：避免页面已切换材料，而 AI 仍使用旧上下文解释结果。见[业务架构](business-architecture.md)。
- 新增本日志，并在 [AGENTS.md](../AGENTS.md) 和 README 中要求同批维护。原因：让后续 agent 理解变更缘由，减少重复讨论和无意改回。
- 通过本地 Kimi CLI 生成三个[原型方向候选](prototype-directions-kimi.md)，并汇编为[Word 选题方案](原型选题方案.docx)。原因：用户希望先选择有大量动画和引导页的原型方向。主 agent 倾向 A，但用户尚未选定；候选不替代当前前端规范。评审要求成功动效绑定真实后端状态、双语只表现句级关系、计数准确且读写区稳定。
- 由本地 Kimi CLI 实现三套可点击原型，保存在 `tmp/corpus-prototype/`，并在 [README](../README.md) 补充启动命令与预览入口。原因：仅凭文字难以判断视觉和动效，需要直接体验引导与研究流程后再选择。原型使用临时示例数据，尚未选定，不替代开发基线。
- 纠正以上两条的模型归属：此前 CLI 的选题与 HTML 实际由默认模型 `DeepSeek/deepseek-v4-pro` 生成，并非 Kimi。撤下旧预览入口，暂停采用旧候选。原因：用户明确要求 Kimi 完成方案与原型，需显式指定官方 Kimi 模型重新生成；GPT 仅整理、归档和审核。
- 使用已核实的实际 Kimi K3（`provider=kimi`、`model=k3`、别名 `kimi-code/k3`）重新生成三案，替换当前[选题方案](原型选题方案.docx)与[原始建议](prototype-directions-kimi.md)；DeepSeek 旧稿按 `2026-10-15-deepseek` 归入 `doc/history/`。原因：落实用户指定模型，避免沿用被误标的旧设计。GPT 仅排版归档；Kimi 推荐 A「星轨观测台」，用户尚未选定。README 恢复新临时原型的本地启动入口，原型采用示例数据，不代表业务实现或运行验收。
