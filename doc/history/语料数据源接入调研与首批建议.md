# 语料数据源接入调研与首批建议

面向高校外语、翻译与语言学研究生的网页语料与 AI 分析平台。核查日期：2026 年 10 月 12 日。本轮查阅发布方文档、许可及数据入口；未注册受限账户、下载整库或完成连接器联调。下文区分已核实事实、接入建议与待验证事项。

## 1. 建议先建立四种有研究价值的数据能力

平台的核心可以确定为：**持续发现和更新多源语料，让研究生在同一个网页中选数据、建研究子库、检索、分析，并保存可复现的研究版本。**

首批来源不宜仅按数据量排序。建议同时覆盖以下能力，先验证研究闭环，再扩大来源数量。

| 能力 | 优先来源 | 学生能完成的研究 | 接入决策 |
|---|---|---|---|
| 中英平行例句 | Tatoeba 文本 | 译法对比、表达检索、翻译例句筛选 | 首批验证 |
| 可持续更新的中英文文本 | Wikipedia 指定项目 | KWIC、词频、搭配、领域词汇、时间版本对比 | 首批验证 |
| 带语言学标注的文本 | UD 指定树库 | 词性组合、依存结构、跨语言句法比较 | 逐树库核准后首批验证 |
| 正式文体的专业翻译 | UN Parallel Corpus v1.0 | 机构话语、术语一致性、正式文体翻译 | 优先候选，先验证下载可达性 |
| 学术论文语言 | OpenAlex 发现层＋许可明确的全文；PMC OA | 学术写作、术语、学科表达比较 | 第二批 |
| 学习者与真实口语 | ICNALE、BNC2014、TalkBank 等 | 二语习得、错误分析、会话分析 | 建立合作与授权路线 |

这些是接入顺序建议，不表示已经取得数据或通过全部授权检查。首版用户界面应分别提供“平台语料库”“我的研究语料”“外部资源目录”，并显示每个来源实际支持的功能。

## 2. 开放文本、平行语料与结构化语料

### 2.1 Tatoeba：最适合先跑通中英句对闭环

官方提供句子、翻译关联、作者及修改时间等导出，周导出每周六 06:30 UTC 更新。文本采用 CC BY 2.0 FR，部分句子提供 CC0；音频另行适用贡献者许可，不能随文本一起默认接入。[官方下载与许可](https://tatoeba.org/en/downloads)

建议直接使用官方文本导出，以 Mandarin Chinese 与 English 的句 ID 连接翻译关系，保留作者和来源。同步时比较句子及关联的增删改，不能只追加新句。社区例句适合译法检索，但不能作为自然语言总体频率基准；官方也不保证译文经过专业校验。[使用条款](https://tatoeba.org/en/terms_of_use)

**首批范围：中英文本和直接翻译边。** 不把两端分别为不同许可的句子统一标成 CC0；不默认通过第三种语言推导出“已验证中英翻译”。

### 2.2 Wikimedia：持续同步的核心文本来源

2026 年官方已推荐新的 MediaWiki Content File Exports。首版适合使用 `mediawiki_content_current` 月度当前修订导出，以 `SHA256SUMS` 判断完整发布并校验文件；不要按旧教程依赖已弃用的 XML 下载路径或旧实验增量机制。[下载门户](https://dumps.wikimedia.org/)、[新导出技术说明](https://wikitech.wikimedia.org/wiki/MediaWiki_Content_File_Exports)

建议先接 `zhwiki`、`enwiki` 正文，保留页面、修订和清洗版本。文本许可及例外需随数据记录；图片另有许可。中英文跨语言链接页面可构成可比语料，不能自动视为句级平行译文。[导出说明](https://dumps.wikimedia.org/other/mediawiki_content_history/readme.html)、[许可说明](https://dumps.wikimedia.org/legal.html)

Wiktionary 后续作为词典资源接入，单独提供词条、词义和词源检索。事件流可辅助追踪近期变动，但不是永久历史存储；第一版采用月度快照更容易核验。[项目映射](https://wikitech.wikimedia.org/wiki/MediaWiki_Content_File_Exports/WikiId_Mappings)、[EventStreams](https://wikitech.wikimedia.org/wiki/EventStreams)

### 2.3 Universal Dependencies：语言学研究的重要入口

UD 提供 CoNLL-U 格式的词元、词性、形态和依存关系，正式发布版本可归档；适合句法检索与标注评估。应保留原句 ID 和 train/dev/test 分区。[发布页](https://universaldependencies.org/download.html)、[格式规范](https://universaldependencies.org/format.html)

许可按树库分别核实。Chinese-GSD 可作为中文优先候选；English-EWT 的 README 则特别区分标注许可与底层文本权利，因此不能只读取一个顶层许可证字段。[UD 许可规范](https://universaldependencies.org/contributing/licensing.html)、[Chinese-GSD 许可](https://raw.githubusercontent.com/UniversalDependencies/UD_Chinese-GSD/master/LICENSE.txt)、[English-EWT 说明](https://raw.githubusercontent.com/UniversalDependencies/UD_English-EWT/master/README.md)

**接入建议：一个已核准中文树库加一个已核准英文树库。** 将树库视为结构化研究材料，避免与大型通用文本混用频率分母。

### 2.4 UN Parallel Corpus：中英正式翻译的高价值候选

发布方论文介绍的 v1.0 含 1990—2014 年联合国文件，覆盖包括中英文在内的六种官方语言，提供文档结构、句子及对齐信息；文中说明该数据集采用公共领域文件，并要求保留免责声明及规范引用。[发布方论文](https://aclanthology.org/L16-1561/)

它适合正式翻译、外交话语和术语研究，应作为固定历史版本。该结论只针对论文说明的这套数据，不能扩展到所有联合国网页内容。本轮[官方数据入口](https://conferences.unite.un.org/UNCorpus/)返回访问错误，当前下载链路尚未验证，不能列为已经可立即入库的来源。

### 2.5 OPUS：用来发现平行语料，按子库接入

OPUS 有语料、语言对和版本发现接口，并提供 XML、XCES、Moses、TMX 等格式。研究用途优先保留文档、句 ID 和对齐结构；仅保留两列句子会损失来源信息。接口文档已核查，具体 API 请求尚未完成连通性验证。[API 文档](https://opus.nlpl.eu/opusapi)、[下载格式](https://opus.nlpl.eu/download-formats)

| 子库 | 研究用途 | 本轮结论 |
|---|---|---|
| WikiMatrix | 跨语言例句与自动对齐研究 | 自动挖掘，有匹配分数；发布方标为 CC BY-SA，具体版本及归属信息补核后再放行。不能标成专业人工译文。[发布说明](https://github.com/facebookresearch/LASER/tree/main/tasks/WikiMatrix) |
| Europarl | 欧洲语言、议会话语、机构翻译 | 原版覆盖欧洲语言，不含中文，属于历史材料；发布页的使用条款不是标准 CC0 授权，平台用途仍需明确。[原始发布页](https://www.statmt.org/europarl/) |
| OpenSubtitles | 字幕翻译、口语化表达 | 有中英文资源和重复字幕问题；本轮未取得足以确认公共平台全文再托管的明确许可，暂不纳入公共镜像。[OPUS 子库说明](https://opus.nlpl.eu/legacy/OpenSubtitles-v2018.php) |

OPUS 连接器的最小配置单位应是“子库＋版本＋语言对＋格式”，不能只有一个“同步 OPUS 全部数据”的开关。

### 2.6 Leipzig 与 Project Gutenberg：后续专题扩展

Leipzig 提供句子、来源、词频和共现等文件，适合词汇研究。部分材料已拆句重排，不适合依赖完整篇章顺序的分析。本轮目标中英文数据包的现行许可未完成核验，暂列条件接入。[格式说明](https://www.wortschatz.uni-leipzig.de/documents/Format_Download_File-eng.pdf)、[官方 FAQ](https://wortschatz.uni-leipzig.de/de/documentation/faq)

Project Gutenberg 适合文学语言、作者风格及历时专题研究。批量访问应走官方指定目录、镜像或下载方式；美国公共领域状态不自动等于其他地区可任意使用，具体作品也有例外，需逐书记录。[自动访问规范](https://www.gutenberg.org/policy/robot_access.html)、[权限说明](https://www.gutenberg.org/policy/permission.html)

## 3. 学术文本：发现文献与取得全文分开

### 3.1 OpenAlex：学术资源发现与全文筛选入口

OpenAlex 的元数据为 CC0。当前官方方案中免费公共快照按季度发布，不能继续按旧资料承诺免费月度或每日更新；更高频能力有独立访问条件。[同步说明](https://help.openalex.org/access/sync/)

当前服务也提供部分作品的缓存 PDF/TEI XML，可通过 `has_content` 和 `content_urls` 发现；所以不能简单称其为“只有元数据”。但论文全文保留原有权利，元数据 CC0 不会覆盖全文。[全文说明](https://help.openalex.org/access/fulltext/)

建议用它发现语言学、翻译学及其他学科论文，筛选许可明确的全文后建库。全文不可得时，仅提供题录检索和来源跳转。上游合并、删除与更新都要处理，不能只累加文献条目。

### 3.2 PMC Open Access Subset：先验证学术全文处理链

PMC OA 子集可用于学术文本处理，但每篇文章许可不同，整个 PMC 也不等于 OA 子集。自动获取必须使用官方指定服务。OAI-PMH 支持按日期和恢复游标获取记录，`pmc-open` 集合与全文格式可用于合规筛选。[OA 子集](https://pmc.ncbi.nlm.nih.gov/tools/openftlist/)、[OAI 接口说明](https://pmc.ncbi.nlm.nih.gov/tools/oai/)

它适合验证章节、摘要、参考文献、术语及学术表达分析。由于内容偏生物医学，不能用其结果代表所有学科的学术英语。首版先挑选允许目标用途的许可类型，保留文章级许可证及段落位置。

## 4. 中文参考库、学习者与口语：优先研究合作接入

这些来源对目标学生很重要。建议继续纳入产品资源地图，但界面应明确“可在本平台分析”“需要机构授权”“前往官方检索”的差别。

| 来源 | 已核实的数据与使用边界 | 产品接入建议 |
|---|---|---|
| BCC | 公开下载中心提供字词频统计，另有在线检索及结果导出；本轮未证实整库全文接口与平台镜像许可。[官方帮助](https://bcc.blcu.edu.cn/help.html) | 统计文件适配与官方导航；统计文件本身不能重建 KWIC、搭配或原文上下文，公开再发布另核准。 |
| CCL | 2026 版有现代、古代和中介语材料；官方旧手册支持有限检索结果导出，不能据此认定整库可同步。[新版公告](https://ccl.pku.edu.cn/news/535/detail)、[使用手册](https://corpus.pku.edu.cn/CCLCorpus_User_Guide.html) | 外部目录与允许范围内的结果导入；结果标为样本，系统迁移后重新核实限制。 |
| BNC XML | 已有免费下载渠道，但公开服务器及文本再分发仍受许可约束；当前网站保留历史条款，应核对实际取得版本附带的许可。[获取说明](https://www.natcorp.ox.ac.uk/getting/index.xml)、[XML 许可](https://www.natcorp.ox.ac.uk/XMLedition/index.xml?ID=licence) | 高校专属参考库候选，不默认跨校共享全文。 |
| BNC2014 Spoken | 注册后可取 XML；许可明确限制再分发和外部云存储。[下载注册](https://corpora.lancs.ac.uk/bnc2014/signup.php)、[许可](https://corpora.lancs.ac.uk/bnc2014/licence.php) | 评估学校自有设备部署与专门授权；学生能下载不表示可以上传公共 SaaS。 |
| BNC2014 Written | 官方工具可研究使用，但因版权原因全文尚不能发布。[官方说明](https://cass.lancs.ac.uk/bnc2014/) | 先提供资源导航，合作前不承诺全文同步。 |
| COCA / English-Corpora | 在线访问与离线数据许可不同；普通离线许可限制第三方语料网站、机构外访问及部分衍生数据发布。[离线介绍](https://www.corpusdata.org/intro.asp)、[使用限制](https://corpusdata.org/restrictions.asp) | 争取覆盖平台用途的合作授权。另记录离线文本的删节缺口，避免把缺口当语言现象。[删节说明](https://www.corpusdata.org/limitations.asp) |
| ICNALE | 学习者作文、口语、修改及评分数据非常匹配目标用户；条款限制复制、再分发，还对对话中的访谈者话语分析设限。[数据模块](https://language.sakura.ne.jp/icnale/download.html)、[条款](https://language.sakura.ne.jp/icnale/index.html) | 优先洽谈学习者研究合作；保留说话人角色，授权前不预装公共全文。 |
| TalkBank / CHILDES | 有儿童语言和会话等材料，访问等级、语料许可和敏感程度不同；部分受保护数据只适合本地分析，网页处理还涉及数据留存条件。[访问分级](https://talkbank.org/0share/access.html)、[使用规则](https://talkbank.org/0share/rules.html) | 按具体子库接入，分别控制音频、转写、说话人信息及外部 AI 传输。 |
| Common Voice / Mozilla Data Collective | 有数据目录、元数据及认证下载 API；下载需先接受条款。MDC 对其分发的 Common Voice 数据禁止再托管、镜像或分享，不能仅凭 CC0 标签推定可建立公共下载库。[API](https://mozilladatacollective.com/api-reference/docs)、[再托管说明](https://community.mozilladatacollective.com/faq-why-cant-i-re-host-or-share-common-voice-datasets-that-i-download-from-mdc/) | 先做目录及授权用途评估，音频研究作为后续专项。 |

暂不收费并不自动满足所有“非商业”或“教学研究”条件；应核对实际使用主体、托管位置与许可用途。许可未明确的能力标为“待核实”，不要把它写成已经禁止，也不要默认启用。

## 5. 对网页端技术设计的直接影响

以下均为本平台的设计建议。

### 5.1 将同步方式做成四类

| 模式 | 示例 | 实现方式 |
|---|---|---|
| 周期全量快照 | Tatoeba、Wikimedia | 检查清单、获取完整文件、校验、按稳定 ID 比较增删改；成功后发布新版本。 |
| 正式版本发布 | UD、UN、OPUS 子库 | 发现 release；按固定版本导入。没有新版本也属于正常状态。 |
| API / 日期游标 | PMC；有权限的其他接口 | 保存游标与时间窗，重叠重试并去重；处理删除和更正，定期对账。 |
| 授权文件与外部目录 | ICNALE、部分 BNC、BCC/CCL 等 | 目录更新、许可核实、授权文件导入。未有正式接口时不模拟整库同步。 |

同步任务统一经过：**发现版本 → 校验接入条件 → 获取文件 → 保存原始对象 → 解析和质量检查 → 构建索引 → 原子发布快照**。失败停留在任务层，用户仍可使用上一可用版本。

### 5.2 统一来源记录，保留语言学差异

来源登记至少包含下列字段。实际实现可以拆成多张表，不能只给每个网站保存一个 URL。

| 字段组 | 最小内容 |
|---|---|
| 来源与版本 | source、subcorpus、upstream_version、language、genre、time_coverage、retrieved_at、原始文件 hash |
| 稳定定位 | 文档 ID、句子 ID、修订 ID、源链接、原始位置、平行对齐边及得分 |
| 更新 | update_mode、manifest、cursor、last_checked_at、last_success_at、删除或撤回记录 |
| 许可证据 | 文本/标注/元数据各自的许可、证据 URL、适用版本、署名要求、核查时间 |
| 操作权限 | 托管、检索展示、全文导出、结果导出、外部 AI 推理、模型训练分别记录 allowed / conditional / prohibited / unknown |
| 质量与处理 | 原生/自动翻译、对齐方式、OCR 或解析状态、缺口、去重簇、分词/标注/清洗版本 |

自然文本、平行句对、树库、词典、统计表、学习者材料和带时间轴的转写分别建模。统一搜索入口可以共用，统计时不能悄悄将这些材料视为相同样本。

跨来源去重应保留“同一文本的多个来源”关系。例如 Wikimedia 原文与 WikiMatrix 抽取句重叠时，既不能丢掉翻译边，也不能在联合词频中重复计数。具体去重口径由分析任务锁定并展示。

### 5.3 同步持续进行，论文数据保持可复现

维护“上游最新版本”“平台已发布版本”“项目研究快照”三个独立状态。项目默认固定语料成员、来源版本、清洗、标注、查询与统计参数；用户主动升级后生成新的研究版本。

上游撤回、隐私删除或许可变化需要独立控制访问。不可变快照不意味着继续公开被撤回内容；必要时撤销文本访问并保存不含受限正文的审计信息，向研究者说明复现受到影响。

### 5.4 AI 与分析引擎分工

| AI 功能 | 建议行为 | 可核验依据 |
|---|---|---|
| 研究问题转查询 | 把自然语言转成可编辑检索条件、筛选范围和统计任务 | 用户能查看实际执行参数 |
| 翻译与例句解释 | 对真实句对解释差异、提出候选归类 | 返回句 ID、原文与来源 |
| 自动编码与辅助标注 | 生成标签建议、置信信息和待复核列表 | 保留原始标注、模型版本及人工修改 |
| 结果解释 | 解读已计算的词频、搭配、关键词和分布 | 引用实际结果表和研究快照 |
| 数据质量辅助 | 标记错对齐、疑似重复、解析问题 | 提供可回查样本，由规则或人工确认 |

精确计数和统计由分析程序完成。生成模型不能凭语感补造频次、p 值或来源句子。外部 AI 推理与模型训练分别登记用途；关闭训练选项也不自动等于服务商零留存。首批不把用户语料用于模型训练。

## 6. 首轮验证计划与验收

下面的数量是建议的试验范围，不是来源总规模，也不是本轮已下载数量。无需先拉取整库即可验证关键风险。

| 验证包 | 建议样本 | 必须证明的能力 |
|---|---|---|
| Tatoeba 中英 | 约 1 万—5 万直接句对 | 来源署名、关联关系、去重、平行检索、周版本差分 |
| Wikipedia 中英文 | 每种语言约 1 千—5 千篇正文 | 清洗、原文定位、词频搭配、页面修订变更处理 |
| UD | 各 1 个许可已核准的中英文树库 | CoNLL-U 无损解析、依存检索、数据分区保留 |
| UN 平行语料 | 下载及包内条件核实后约 1 万—5 万句对 | 文档结构、术语对比、一对多对齐及引用 |
| 学术全文 | 第二批约 500—2 千篇许可明确文章 | 题录与全文区分、章节结构、文章级许可、术语分析 |

验收要求：

1. 同一导入重复执行不产生重复数据；失败后能续传或安全重跑。
2. 任一检索命中都能回查来源、上游版本和原始定位；缺失上下文明确标注。
3. 词频、搭配、关键词等结果包含实际语料范围与分母；抽样结果不冒充全库结果。
4. 新数据发布后，旧研究快照的结果不被静默改写。
5. 权限分别作用于正文展示、导出和 AI 传输，目录条目不能被误认为可分析全文。
6. 模拟新增、修改、删除与授权变化；验证缓存、索引和导出入口执行相同策略。
7. 对抽样解析与对齐做人工核验，并记录质量指标，再决定扩大数据量。

## 7. 本轮结论与尚未验证的部分

首版最值得验证的是 **Tatoeba＋Wikipedia＋指定 UD 树库**；UN 中英材料作为紧随其后的专业翻译库候选。学术全文通过 OpenAlex 发现及许可筛选、PMC 官方通路补充。学习者与真实口语数据应同步启动合作研究，不需要为了追求来源数量提前承诺公共全文托管。

当前仍需完成：真实文件的小样本下载与解析、目标包内 LICENSE 核对、部分 API 连通性与限额测试、UN 当前下载可达性验证，以及受限库的平台用途授权确认。本轮确认了来源类型与接入路线，没有声称已同步任何语料。

建议以这一数据源分层修订网页技术设计：先把来源注册、版本同步、研究快照和来源引用做成核心模块，再增加更多分析与 AI 工具。
